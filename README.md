# 通用剧情记忆（SillyTavern 扩展）

适用于**所有角色卡**，无任何卡片专属逻辑。要求 SillyTavern 1.12 及以上。当前版本 1.1.3。

## 1.1.3 更新了什么
- **默认关闭，避免白烧 token**：首次安装、或尚未保存过本插件设置时，「启用插件」「自动总结剧情」「总结时自动提取关键词条目」默认均为关闭。此时不会自动总结、不会自动提取关键词、也不会向提示词注入记忆。
- 需要使用时，打开扩展设置抽屉 **「通用剧情记忆」**，勾选 **启用插件**。若还要自动总结，再勾选 **自动总结剧情**；若要在总结时提取关键词，再勾选 **总结时自动提取关键词条目**。
- 「立即总结」、导出/导入、手动编辑条目等按钮在总开关关闭时仍可点击使用。「启用插件」关闭时，已有记忆也不会注入到提示词。
- **已安装旧版并保存过设置的用户**：已保存的开关状态会覆盖新默认值，不会被这次更新强制关掉。若要停止自动消耗 token，到同一设置面板取消勾选「启用插件」（建议同时取消「自动总结剧情」）。


## 功能
- **自动剧情总结**：每 N 条消息（默认 10）用当前 API 静默生成总结，追加到本聊天的长期记忆，并按设定深度/位置注入提示词。新安装时默认关闭，需在设置里勾选「启用插件」和「自动总结剧情」后才会自动运行。
- **关键词记忆**：总结时让模型输出 JSON，自动提取新设定/人物/事件为条目；每次生成前扫描最近几条消息，命中关键词即注入对应条目。
- **独立总结 API**（可选）：总结和提取关键词可走另一套 OpenAI 兼容接口，主聊天仍用酒馆自己的连接，不带角色卡和预设。默认关闭，行为与 1.1.0 完全相同。
- **记忆导入 / 导出**：把当前聊天的总结和关键词条目导出为 JSON，再导入到新角色卡、新聊天中接着用。支持覆盖或合并；手机或云端酒馆也可用「复制到剪贴板」和「从文本导入」。
- **设置面板**（扩展抽屉内）：开关、间隔、深度、位置、可编辑的总结提示词模板、独立总结 API、查看/编辑/清空总结、编辑/删除/新增条目、"立即总结"按钮，以及导出/导入记忆。

## 安装
1. 方式一：把整个 `st-memory` 文件夹放到 `SillyTavern/public/scripts/extensions/third-party/`，刷新页面。
2. 方式二：扩展面板 →「安装扩展 / Install extension」→ 填入本插件的 git 仓库地址。
3. 若已安装旧版：用本目录五个文件覆盖原扩展文件夹后，刷新页面（或在扩展面板中更新）。覆盖后版本应显示为 1.1.3。

## 独立总结 API
位置：扩展设置抽屉「通用剧情记忆」里，在「恢复默认模板」按钮下方、「立即总结」按钮上方，标题为 **独立总结 API**。

1. 勾选 **启用独立API**。不勾选时，总结仍走酒馆当前连接（`generateQuietPrompt`），和 1.1.0 一样。
2. 填写 **API 地址**（OpenAI 兼容的 base URL）。可以只写到 `/v1`，也可以带上 `/chat/completions`，插件会自动整理。
3. 填写 **API Key**（密码框）和 **模型名**。可选填写最大 Token、温度；留空则不发送这两项，由服务端默认。
4. 点 **测试连接** 发一条极短请求，成功或失败会用提示框说明。点 **获取模型列表** 会请求 `GET …/models`，把结果填进模型名的下拉候选（仍可手打）。
5. 之后「立即总结」和自动总结都会用这套独立接口：`system` 为插件的总结指令，`user` 为已有总结和最近对话，**不带角色卡、预设和酒馆聊天注入**。主聊天不受影响。
6. 若接口返回 HTTP 错误，会提示状态码和错误信息，**不会改写**已有总结和词条。

### 填写示例

**OpenRouter**（本机 2026-11-24 实测：预检和 `GET /v1/models` 均带 `Access-Control-Allow-Origin: *`，网页可直接请求）：

- API 地址：`https://openrouter.ai/api/v1`
- API Key：OpenRouter 的 `sk-or-…` 密钥
- 模型名：例如 `google/gemini-2.5-flash`（以 OpenRouter 模型页为准；也可用「获取模型列表」）

**Google AI Studio 的 OpenAI 兼容接口**（官方文档：`https://generativelanguage.googleapis.com/v1beta/openai/`。本机 2026-11-24 实测：对该路径的 `OPTIONS` 预检和错误 `POST` 都会返回 CORS 头，允许 `authorization` 与 `content-type`。未用真实密钥测通过的 200 响应）：

- API 地址：`https://generativelanguage.googleapis.com/v1beta/openai`
- API Key：Google AI Studio / Gemini API 密钥（作 Bearer 使用）
- 模型名：填写 Gemini 的模型 ID（例如文档中的 `gemini-2.5-flash` 或你当前能用的型号），不要填 `gpt-4o`
- 「获取模型列表」在未带密钥时，此兼容路径的 `/models` 曾返回 404，若失败请手动填写模型名

### 跨域（CORS）
浏览器扩展是从酒馆页面发起 `fetch` 的。本插件会**优先**走酒馆自带的后端转发：`/proxy/https://…`（需在酒馆根目录 `config.yaml` 设置 `enableCorsProxy: true` 或启动参数 `--corsProxy`，默认关闭；改完须重启）。若探测到代理未开启，再改为浏览器直连。

直连时：OpenRouter 允许浏览器跨域（已测）。Google 的 OpenAI 兼容接口也会返回 CORS 头（已测预检和错误响应）。其他服务若未开放 CORS，直连会失败，提示里会说明可开启上述代理。官方 OpenAI 接口未在此验证，请不要默认它能从网页直连。

**请注意：API Key 会明文保存在酒馆的 `extension_settings` 里**（保存在本地设置，并非写进角色卡）。不要把带密钥的设置文件发到公开位置。云端或多人共用的酒馆尤其要小心。

## 导出 / 导入记忆
用于「新开一张角色卡 / 新开一个聊天，但接着用原来的记忆」。

1. 在**原来的聊天**里打开扩展设置「通用剧情记忆」，点「导出记忆」，会下载一个 JSON 文件（文件名含角色名和日期时间，例如 `记忆_角色名_2026-11-24_1653.json`）。下载不方便时，可点「复制到剪贴板」。
2. 打开新角色卡，并新开一个聊天。
3. 再打开本插件设置，点「导入记忆」选择刚才的文件；或把 JSON 粘贴到「或粘贴记忆 JSON 后导入」文本框，点「从文本导入」。
4. 先会确认是否导入到**当前聊天**。若当前聊天已有记忆，再问覆盖还是合并：
   - **覆盖**：用导入的总结和条目替换当前聊天的全部记忆。
   - **合并**：把导入的总结追加到现有总结末尾；条目按关键词去重后加入——若与已有条目有任一关键词重叠，则合并到该条目（关键词取并集；导入内容与已有不同则追加在后），否则新增一条。
5. 导入只写入当前聊天的记忆，不会改角色卡本身，也不会把旧聊天的消息进度（`lastIndex`）原样套过来。自动总结会从当前聊天已有消息之后继续，避免把新卡开场白再总结一遍，或因旧进度而长时间不总结。

导出文件是 UTF-8 的 JSON，主要字段为 `type`（固定 `st_memory`）、`summary`、`entries`（每条含 `keywords` 与 `content`）。也会附带 `version`、`exportedAt`、`character`、`lastIndex` 等元数据，导入时只使用总结和条目。

## 注意
- 总结和条目**按聊天保存**（存在聊天元数据里），换聊天/新开聊天各自独立；全局设置（含独立 API 的地址、密钥、模型）保存在 extension_settings。要把记忆带到新聊天，请用上面的导出/导入。
- 未启用独立 API 时，总结会消耗一次酒馆当前连接的 API 调用；启用后则消耗独立接口的额度，不再走酒馆那次静默生成。
- 模型若没按 JSON 输出，整段回复会被当作总结，不提取条目。
- 删除消息后不会自动回滚已有总结，可手动编辑。
- 导入前请确认已经打开目标聊天，否则会提示无法导入。
